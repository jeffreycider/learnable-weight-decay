# Resume after a qualified execution change

A `resume_compatibility` declaration can permit explicitly named performance settings and exact source-hash transitions while restoring the actor, Adam moments, private probes, dual variables, data cursor, RNG state and training clock. The declaration itself is SHA256-pinned in YAML. Ordinary resumes remain strict.

Only cache capacities, sensor normalization caching, and the compiled raw-logit objective are eligible configuration changes. Architecture, objective coefficients, optimizer settings, examples and schedules must still match the source checkpoint. Every changed source file must match both the declared old and new hashes; a declaration is an audit record of prior qualification, not proof that arbitrary source edits are equivalent.

Record the declaration alongside the new run's recipe. Use a new output directory so the original run and its immutable checkpoints remain intact.
